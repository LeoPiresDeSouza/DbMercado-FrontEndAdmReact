# Internacionalização (admin)

O painel administrativo usa **react-i18next** com carregamento preguiçoso dos JSON em `src/shared/i18n/locales/{pt-BR,en-US,zh-CN}/`.

## Idiomas e armazenamento

| Item | Valor |
|------|--------|
| Idiomas | `pt-BR`, `en-US`, `zh-CN` |
| Chave `localStorage` | `dbmercado_admin_locale` (constante `ADMIN_I18N_STORAGE_KEY` em `constants.ts`) |

A detecção segue: `localStorage` → navegador → `htmlTag`; o idioma ativo também atualiza `document.documentElement.lang`.

## Namespaces

`common`, `auth`, `dashboard`, `users`, `roles`, `audit`. No boot só `common` é carregado; os demais entram sob demanda (dynamic `import()` em `lazyJsonBackend.ts`).

## Onde colocar textos

- **Telas / layout:** `useTranslation('namespace')` (ou array de namespaces) e chaves no JSON correspondente.
- **Erros de API / rede:** códigos estáveis em `shared/constants/errorCodes.ts` e mensagens em `common.json` → `errors.*`; a função `resolveLocalizedErrorMessage` (usada no login e no dashboard) traduz `NormalizedHttpError` com fallback HTTP, timeout, `Failed to fetch`, etc.
- **Login sem mensagem do servidor:** `AUTH_LOGIN_FAILED_CODE` → `auth.json` → `errors.loginFailed`.
- **Toasts do SignalR:** textos em `common.json` → `realtime.*`; `mapEventToNotification.ts` usa a instância global `i18n` para manter o idioma atual quando o hub dispara eventos fora do React.

## Package compartilhado (futuro)

Para reutilizar no mobile, extraia a pasta `locales/` junto com `constants.ts` e `lazyJsonBackend.ts` (ver comentários nesses arquivos). Mantenha a mesma hierarquia de chaves para facilitar diff e revisão.
